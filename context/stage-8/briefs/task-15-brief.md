## The agent: tools/pace-agent/pace_agent.py (Python 3.9+, standard library only)
- Probes (one module-level function per OS, swappable in tests): `front_app() -> str | None` and `idle_seconds() -> float`.
  - Windows: ctypes — user32.GetForegroundWindow, GetWindowThreadProcessId, kernel32.OpenProcess +
    QueryFullProcessImageNameW (exe base name without .exe, then a friendly name via the exe's FileDescription if cheap, else
    the base name), user32.GetLastInputInfo + kernel32.GetTickCount64 for idle.
  - macOS: `lsappinfo info -only name $(lsappinfo front)` (parse the "name" value) for the front app; `ioreg -c IOHIDSystem`
    HIDIdleTime (ns) for idle. No Accessibility permission needed.
  - Linux X11: `xdotool getactivewindow getwindowpid` → /proc/<pid>/comm (or the WM_CLASS via `xprop` if xdotool lacks pid);
    idle via `xprintidle` (ms). Wayland: KDE `kdotool getactivewindow getwindowpid` if present; GNOME Wayland: no generic way
    → the agent prints a clear message and only reports idle/active via `gdbus call --session --dest org.gnome.Mutter.IdleMonitor
    … GetIdletime` with app name "unknown"? — keep it simple: report "Unsupported desktop (GNOME on Wayland)" at install and
    exit non-zero; document it.
- Loop: sample every 5 s; a sample counts as active when idle < 60 s (`IDLE_AFTER_SECONDS`); consecutive active samples of the
  same app join into a session; a gap < 60 s of the same app joins (as the bridge did); sessions < 60 s are dropped; every 5 min
  (`SEND_EVERY_SECONDS = 300`) send finished sessions (and the running one cut at now) to `/api/usage/sessions` with the agent
  token (same body shape as the bridge); keep unsent sessions in a JSON buffer file in the config dir and retry with backoff;
  cap the buffer (e.g. 7 days).
- Commands: `install --token T --api URL [--name NAME]` (saves config: Windows %APPDATA%\Pace, macOS ~/Library/Application
  Support/Pace, Linux ~/.config/pace; registers autostart: Windows Task Scheduler at logon running `pythonw pace_agent.py run`
  via `schtasks /Create /SC ONLOGON /RL LIMITED /TN "Pace agent" /TR …`; macOS a LaunchAgent plist in ~/Library/LaunchAgents
  with KeepAlive, loaded with `launchctl bootstrap gui/$UID`; Linux a systemd user service `pace-agent.service` enabled and
  started), `run`, `run --logs` (prints each sample decision and each send body instead of sending — "what it would send"),
  `status` (config, last send, buffer size), `uninstall` (removes autostart and config).
- Install one-liners generated by the app (the token inlined): 
  - Windows (PowerShell): checks `python`/`py`, if missing `winget install -e --id Python.Python.3.12`, downloads the script
    from `${WEB_ORIGIN}/pace_agent.py` to %APPDATA%\Pace and runs install.
  - macOS / Linux (Terminal): `curl -fsSL ${WEB_ORIGIN}/pace_agent.py -o ~/.pace_agent.py && python3 ~/.pace_agent.py install
    --token … --api …` (macOS: python3 comes with the Command Line Tools — mention the prompt; Linux: note xdotool + xprintidle
    packages for X11: `sudo apt install xdotool xprintidle` / dnf / pacman lines).
- Tests: tools/pace-agent/test_pace_agent.py (unittest; probes stubbed; time injected): sessions joining, idle cut, short
  sessions dropped, buffering on send failure and flush on success, send body shape, `--logs` output, config paths per OS,
  the generated autostart files (plist, service unit, schtasks command line) as strings. Update `test:unit` in package.json to
  discover tools/pace-agent instead of the bridge.
- Delete tools/pace-aw-bridge and serve pace_agent.py from the web build instead (scripts/build-web.ts).
