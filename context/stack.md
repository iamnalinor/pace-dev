# Стек

Технологические решения. Требования — в основной вкладке; здесь только то, на чём это строится.

## Язык и репозиторий

- TypeScript везде: одна и та же логика (формулы, материализация событий, пресеты) работает на телефоне, в вебе и на сервере.
- Монорепо: Bun workspaces + Turborepo.
- Пакеты: `core` (схема событий, материализаторы, формулы срочности, политики, пресеты), `app`, `web`, `server`.

## Компоненты

| Слой | Выбор |
| --- | --- |
| Android | Expo (React Native); `expo-calendar` для календарей телефона; свои Kotlin-модули на Expo Modules API — `UsageStatsManager` (экранное время, разблокировки для сна) и «Не беспокоить»; share intent; `expo-notifications` поверх FCM |
| Веб | Vite + React, SQLite в WASM (OPFS) для офлайна |
| Дизайн | Общие токены: Tailwind в вебе, NativeWind в приложении |
| Синхронизация | LiveStore (event sourcing, локальная SQLite). План Б — своя синхронизация событий push/pull по курсору через Durable Object |
| Бэкенд | Cloudflare Workers, бесплатный план |
| Данные пользователя | Durable Object на пользователя (SQLite): лог событий, проекции, журнал решений, alarms для уведомлений и дайджестов |
| Общие данные | D1: вайтлист, сессии, связь Telegram ID с пользователем |
| Telegram-бот | GramIO на вебхуке, проверка `secret_token` |
| MCP | Cloudflare Agents SDK, OAuth через `workers-oauth-provider`; read-only SQL с ограничителем и готовые саммари |
| Авторизация | Telegram: Login Widget в вебе, deep link в бота для Android; вайтлист по Telegram ID |
| LLM | Vercel AI SDK (провайдер-агностично), structured output по строгой схеме, проверка по исходному тексту; бесплатная модель, выбор — по регрессионному набору |
| Тесты | Vitest, включая регрессионный набор разбора LLM |

## Правила под бесплатный план Cloudflare

- Чтение только из проекций и по индексам, без полных сканов лога; у SQL из MCP — ограничитель.
- Синхронизация через WebSocket Hibernation API или запросами — без постоянно активного Durable Object.
- Тяжёлые пересчёты (ретро-правки) — внутри Durable Object, а не в обычном Worker с лимитом CPU 10 мс.
- Дайджесты и напоминания — на alarms Durable Object, а не на Cron Triggers (их 5 на аккаунт).
- Все эндпоинты с LLM — только за авторизацией.

## Проверить в спайке

Спайк — короткий эксперимент с жёстким таймбоксом (1–2 вечера), который отвечает на рискованный вопрос до основной разработки. Код выбрасывается; результат — решение: берём, берём с обходом или переходим на запасной вариант.

- [ ] **Синхронизация.** Минимальное Expo-приложение с LiveStore: одна таблица, кнопка «добавить событие», синхронизация через Cloudflare между телефоном и вебом. Отдельно — событие с прошлым `occurred_at` и как оно попадает в проекцию. Не заводится — план Б, своя синхронизация.
- [ ] **Бот.** Worker с GramIO, отвечающий «pong» через вебхук. У `@gramio/core` на JSR совместимость с Workers не отмечена; запасные варианты — grammY (официальный гайд для Workers) или `@gramio/wrappergram`.
- [ ] **Монорепо.** Bun workspaces + Turborepo, где Expo-приложение и Worker импортируют общую функцию из `core`.
- [ ] **Календари.** Экран со списком календарей телефона через `expo-calendar` — виден ли Exchange.
- [ ] **Лимиты.** Durable Object с заведомо тяжёлым циклом — где упираемся в CPU на бесплатном плане.

## Не решено

- [ ] LLM-провайдер для рабочих задач без обучения на данных.
