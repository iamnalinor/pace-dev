## Summary

**24 findings: 0 blocker · 11 major · 9 minor · 4 nit.** Verdict under the skill: **Block.** The skill's block
criteria that apply: an entrance from `scale(0)` (the desktop dialog), linear or ease-in-out easing on every
entrance, a 750 ms animation on an action done tens of times a day, and reduced motion treated as "off".

The three things that matter most:
1. **Checking off a task takes about a second, and most of that second is empty.** Measured on the phone web
   build: the check fills 238 ms after the press, because the same commit mounts 150 animated specks (a 229 ms
   long task). The row's content is gone by about 780 ms. An empty slot then sits until 1064 ms. After that the
   rows below **jump** into place: the layout transition does not run on the web at all. The Undo toast arrives
   at 1117 ms with no motion of its own. Under reduced motion the row turns into a **blank hole, check included,
   for about 800 ms**. This is the owner's feedback-4 complaint ("shorten the pause"), still present
   (04-001…004).
2. **The motion tokens have no easing and no exits.** None of the `motion.ts` presets sets an easing, so
   Reanimated falls back to **linear on the web** and **ease-in-out(quad) on Android**. Every entrance fails
   standard 3. The desktop dialog's `ZoomIn` grows from **`scale(0)`**. The sheet travels a full window height.
   Every sheet and dialog **disappears in one frame** (18–25 ms), although the Stage 8 plan promised an exit
   animation. Reduced motion switches everything off instead of making it gentler (04-005…009, 04-004).
3. **Animation fires where it should not, and not where it should.** Switching days on Day crossfades two whole
   timelines over each other. Changing a filter on Now re-fades the rows that stayed and cuts the rows that left.
   Every list fades all its rows in at once on mount. Meanwhile the toast, the time-bar disclosure, route pushes
   on the web and press feedback have no motion at all. The composer unfold still shows the form header clipped
   for its first frames (04-010…016, 04-020).

Verified fixed: the scrim no longer rides up with the sheet (feedback-2): it fades in place, 180 ms. The slider
no longer jumps after release (feedback-3): no value change after `pointerup`, `R04/slider.json`. No
flash-back of a dissolved row appeared in any recording (feedback-4).

## Skill verdict (Part 2, by impact tier)

1. **Feel-breaking regressions:** check-off latency and length (04-001, 04-002); `scale(0)` dialog (04-005);
   linear and ease-in-out entrances (04-007); crossfades on day switch and filter (04-010, 04-012); the
   reduced-motion blank hole (04-004).
2. **Missed simplifications:** remove row animations on dataset swaps, filters and hotkeys (04-010, 04-012,
   04-013, 04-022); calm or remove the pulse (04-017).
3. **Performance:** 150 React views per dust run (04-002); `height` animated on the composer and the update
   strip (04-014, 04-018).
4. **Interruptibility and timing:** sheets and dialogs have no exit at all (04-006); the toast has no
   interruptible enter or exit (04-016).
5. **Origin, physicality, cohesion:** sheet travels the full window height (04-008); tooltip has no origin
   (04-019); three disclosure behaviours (04-015); the web and Android differ on row close-up and push (04-003,
   04-024).
6. **Accessibility:** reduced motion means off, not gentler (04-004); press feedback and ripple (04-020).

**Decision: Block.**

## What this says about the system

- **The tokens are durations without curves.** `motion.ts` never sets an easing, so each platform picks its own
  default: linear in Reanimated's web CSS path, ease-in-out(quad) in `withTiming` on Android. Every entrance in
  the app is therefore wrong in two different ways. The new motion spec must own the curves (STANDARDS'
  `--ease-out`, `--ease-in-out`, `--ease-drawer`) and pass them explicitly everywhere.
- **Enter-only thinking.** Presets exist for enter (`ROW_ENTER`, `SHEET_ENTER`, `DIALOG_ENTER`,
  `BACKDROP_ENTER`), but sheets, dialogs, toasts and tooltips have no exit. The plan's exit (plan.md:196) was
  never built. Every primitive in the spec needs a paired enter/exit, with the exit about 0.75× the enter.
- **Row animations are attached to rows, not to user actions.** `entering`/`exiting`/`layout` live on every
  list item, so they fire on mount, filter, day switch, remount and hotkeys, which are exactly the
  high-frequency cases standard 2 forbids. Meanwhile the one case that needs them (a single row leaving after a
  check) does not animate on the web. Motion should be triggered by an action ("this row was added or removed by
  you") with lists skipping on mount and on dataset change.
- **Reduced motion is a kill switch, not a profile.** `ReduceMotion.System` zeroes everything, including
  opacity fades that aid comprehension. Code that pairs an animation with a fixed timer (the dust's
  `setTimeout`) then breaks under it. The spec needs a reduced variant of each preset (fade-only, short), and
  timers driven by animation completion, not by constants.
- **Web is assumed to behave like Android, and nobody watches frames.** Bug-lesson 11 covered Android
  flattening, but no check looks at whether a transition runs on the web. The layout transition is dead there,
  the dialog grows from 0, and a first frame may flash. The e2e geometry sampler (`expectStaysInside`) should
  grow into a motion sweep: for each primitive, assert multi-frame movement, the end state and the clipping,
  with normal and reduced motion.
- **Motion lives in components, not in one module.** The 750, 220, 300 and 900 ms values, the 150-speck
  particle system and the class-swap `scale-110` sit in leaf files, and press feedback is 43 copies of
  `active:opacity-*`. The kit needs one `Pressable` (ripple on Android, scale/tint on the web), one
  `Disclosure`, one `Presence` (enter/exit with reduced variants) and one `Sheet` that keeps itself mounted
  through its exit.
- **Owner signals map one-to-one to the classes above.** The scrim complaint (feedback-2) is fixed. The unfold
  clipping (feedback-4) persists as clipped first frames because of the hard swap and the slow-start curve. The
  "pause before rows close up" (feedback-4) persists because the dust's timer outlives its content and the
  close-up does not run on the web.
