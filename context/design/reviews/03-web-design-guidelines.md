# 03: Web layer against the Web Interface Guidelines

Reviewer 03. Method: `dev-core:web-design-guidelines` (Vercel Web Interface Guidelines,
vendored @434b7f9). Every rule in `guidelines.md` was checked against the web-only layer:
`apps/app/src/**/*.web.ts(x)`, `global.css`, `src/platform/web/`, `metro.config.js`
(`WEB_SHIMS`), `public/`, `scripts/build-web.ts`, `scripts/serve-web.ts`, and the built
`dist/index.html`, manifest and service worker. Most of the evidence comes from the **live build**
at `http://localhost:4173`. Playwright read the computed styles and DOM of 16 routes in three
combos (desktop-dark-en, desktop-light-ru, phone-dark-ru), walked 45 Tab stops on 5 routes in
both themes, and tested an OS-vs-app theme mismatch, forced colors, real scrollbars, wheel
scrolling and a draft reload. Accounts used: Telegram ids 3200 (RU), 3201 (EN) and 3202 (empty).
Raw JSON (`audit.json`, `focus.json`, `misc.json`, `sem.json`) and screenshots are in
`/tmp/claude-0/-home-user-pace-dev/23f43a3c-f01c-576a-9968-19b7d8385587/scratchpad/review-03/`. Below, `S/` stands for
that folder. The scripts (`r03-*.ts`) are in the scratchpad's `shots/` folder; `r03-wheel.ts`,
`r03-draft.ts` and `r03-scrollkeep.ts` print their results to stdout.

## Summary

**29 findings: 1 blocker, 6 major, 16 minor, 6 nit.** The head metadata, font pipeline, reduced
motion, touch and SW basics are solid (see "Passes"). The three that matter most:

1. **Text fields show no keyboard focus at all (03-001, blocker, WCAG 2.4.7).** `global.css:44-47`
   removes the outline. Of the ten distinct text fields reached by Tab, only the composer card draws
   a replacement. On every sampled route, 9 Tab stops per theme land on a field that looks exactly
   like its resting state.
2. **The document ignores the in-app theme (03-002).** `color-scheme`, `theme-color` and the body
   background follow the OS, not `pace.theme`. A dark app on a light OS gets a white scrollbar
   gutter, a light status/URL bar on Android, and a ~240 ms light flash on every load.
3. **Navigation is not made of links (03-003) and the title never changes (03-004).** The signed-in
   app has **zero `<a>` elements**: 341 `div[role=link]` without `href`, so Ctrl/Cmd/middle-click,
   "Copy link" and new-tab do nothing (verified). `document.title` is "Pace" on every route.

Also major: the tooltip cannot be hovered (WCAG 1.4.13, 03-005), forced colors erase every selected
state and primary-button shape (03-006), and the desktop scroller is the 880 px column, so the
scrollbar floats mid-window and the wheel is dead over 336 px of gutters (03-007).

## What this says about the system

- **The web layer has no document-level owner.** `ThemeProvider` paints a `View`, and nothing owns the
  `<html>` element (`color-scheme`, `theme-color`, background, `lang` at first paint, `title`). Only
  `lang` got a `.web.tsx` effect. 03-002, 03-004, 03-016 and 03-022 are one missing piece: a
  `src/platform/document-*.web.tsx` set, plus a CSP-compatible `public/theme-boot.js` for first paint.
- **Interaction states are left to the browser.** Focus is either removed (fields) or left to the UA
  default (everything else). There is no focus token, no hover layer and no forced-colors or contrast
  variant, so the same gap shows up as 03-001, 03-006, 03-019 and 03-020. The spec needs a state
  matrix (rest, hover, pressed, focus-visible, selected, disabled) as tokens, rendered by the kit and
  backed by a single `global.css` section, not per component.
- **Selected state is colour-only.** Chips, sidebar and tabs convey "current" by fill alone, so it
  vanishes in forced colors (03-006) and reads as nothing to assistive tech wherever
  `aria-checked`/`aria-current` is missing (03-009). Every selected state needs a non-colour carrier
  (an outline/border or a check glyph) plus the ARIA state.
- **RN abstractions erase web semantics by default**: `div[role=link]` without `href` (03-003),
  `role=heading` that always becomes `<h1>` (03-008), a `Text` instead of `<label>` (03-028),
  `autocomplete="on"` (03-011), a `tablist` for navigation (03-009). The kit should expose
  semantic props (`href`, `level`, `labelFor`, field `purpose`) once, so screens cannot get them wrong.
- **Desktop layout is phone layout, centred.** The 880 px scroll column (03-007) gives a mid-window
  scrollbar and dead gutters. The desktop shell should own scrolling at the window level.
- **Typography rules live in no shared place.** Tabular digits are a per-site class (03-013), and
  RU spacing and units are hand-typed (03-014). The type scale should define a "numeric" style, and
  the i18n tests should guard NBSP/unit rules the way `contrast.test.ts` guards colour.
- **Local serving does not match production** (no `_headers`, 03-026), so the web constraints
  (CSP) that shape the fixes above are invisible to tests.
