# 08 — Accessibility of the incumbent UI, measured

Reviewer 08-a11y · commit `057e484` · web build `http://localhost:4173` (production export) · Telegram ids 3280–3282
(seeded lived-in accounts, English UI, Russian user content, `timezoneId: Europe/Moscow`).

**Summary.** 30 findings: **8 blocker** (WCAG 2.2 A/AA failures), **11 major**, **8 minor**, **3 nit**. axe-core
(WCAG 2.2 AA tags, every impact level) reports **0 violations** over 21 routes × 390/1440 × light/dark (84 page
states) plus 16 open-overlay states (four sheets/dialogs and the toast, both themes and viewports) — every failure
below is one axe cannot see (focus, zoom, timing, semantics, non-text contrast of composited layers, hotkeys,
titles). The contrast table covers 131 real token pairs × 2 themes = 262 rows: 27 rows fail WCAG (2 of them text:
light `faint` 4.19:1), 77 more pass WCAG but fail APCA — **60 of those are dark-theme text**. What matters most:

1. **The keyboard and low-vision basics are not designed.** Text fields have no focus state at all (11 inputs,
   e.g. 2/33 stops on Now, 5/58 on Settings); every other stop relies on Chromium's default ring, drawn round an
   invisible 44 px box and clipped inside sheets; `n`/`f` are single-key global shortcuts with no off switch;
   every route is titled "Pace".
2. **Boundaries and states live in fills that are 1.1–1.4:1** (`line`, `track`, `raised`, field-on-surface,
   light project fills): text fields, the selected task row and the light colour marks are not perceivable at
   the 3:1 non-text minimum, and all of it disappears under forced colours.
3. **Fixed chrome eats the viewport**: at 200 % zoom Now keeps ~120 px for its list; at 400 % the time bar +
   tab bar (260 px) are taller than the viewport (225 px) and the task list is unreachable (1.4.10).

Positives worth keeping: reduced motion is honoured end to end (sheet/dialog enter animations measured off under
`reduce`); sheets trap focus, close on Escape and return focus to the trigger; no 2.5.8 failure on the web (all
targets ≥ 24 px); no horizontal scroll at 320 px; text-spacing override (1.4.12) breaks nothing; rendered colours
match `tokens.json` exactly (9 samples × 2 themes checked against computed styles).

## What this says about the system

- **Accessibility is enforced only where a tool already looks.** `contrast.test.ts` checks text tokens on
  `bg`/`surface` and marks at 3:1, and e2e fails only on axe serious/critical — so every gap is in what neither
  sees: composited layers (`line`, `track`, washes over `bg`, field fill on surface), states drawn as fills,
  focus, zoom with fixed chrome, timing, titles, hotkeys, heading levels. The spec must turn each class into an
  assertion (below), not a checklist line.
- **No state layer in the kit.** Focus, selection, hover and pressed are ad hoc per component (opacity 0.7/0.75/
  0.8, four disabled opacities, fills at 1.1:1, the browser's outline). The new kit needs one state model —
  rest/hover/pressed/focus-visible/selected/disabled — with tokens that carry contrast guarantees (`focus`,
  `selected`, `field-border` ≥ 3:1) and a forced-colours mapping.
- **"Boundary by hairline" is the house style, and it is below 3:1 in both themes.** Decorative dividers may stay
  quiet; anything that identifies a control (fields, selected rows, chips, colour marks) needs a ≥ 3:1 edge.
- **The dark palette was tuned to WCAG 2's formula, which flatters light-on-dark.** Dark secondary text is
  Lc 33–40; build the next palette against APCA (or both) so the two themes read alike.
- **Sizes are rem-based on a platform where rem ≠ the target unit.** Targets, field heights and text boxes should
  be px/dp tokens (or `inlineRem: 16`), so "44" and "48" mean the same on Android and the web.
- **Semantics are mapped 1:1 from React Native roles without the web's extra structure**: `header` → h1
  everywhere, `tab` for navigation, labels on role-less views (dropped), no `main`, no titles. A thin web
  semantics layer in the kit (`ScreenTitle` h1 + `<title>`, `SectionTitle` h2, `role="main"`, `Group` with
  `aria-labelledby`) fixes all screens at once.
- **Assertions that should become tests:**
  1. *Unit* (`packages/core/src/design/contrast.test.ts`): generate the pair list from a `USED_PAIRS` table in core
     (text × ground incl. `raised` and the wash-over-`bg` case; non-text: `field-border`, `selected`, `focus`,
     project marks per theme) and assert WCAG ≥ 4.5/3 **and** APCA ≥ the role's Lc (port `R08/contrast.ts`'s
     `apca()`, which reproduces the reference values); fail on any text use of a token absent from the table.
  2. *e2e focus sweep*: Tab through Now, Day, task pane, Week, Settings and one sheet; every stop must have a
     computed outline/box-shadow that differs from its unfocused style and lies inside the viewport, not under
     a fixed footer; sheets must trap Tab, close on Escape, and return focus to the trigger; after delete/inline
     confirm, `document.activeElement !== body`.
  3. *e2e axe*: keep the gate on serious/critical but also fail on `aria-dialog-name`, `landmark-one-main`,
     `aria-required-children`, `aria-prohibited-attr` (add `best-practice` to the tags with an allowlist), and run
     it with each sheet open and with `forcedColors: "active"`.
  4. *e2e zoom*: at 720×450 and 320×256 the first task row is reachable and fully visible when focused.
  5. *e2e reduced motion*: with `reducedMotion: "reduce"`, opening a sheet yields `document.getAnimations()` empty.
  6. *e2e titles and headings*: every route has a unique `document.title`, exactly one h1, no other heading at
     level 1.
  7. *jest (native preset)*: kit components' rendered min height/width ≥ 48 (Android) given 1 rem = 14 px;
     no single-key hotkey registered without a modifier unless the setting is on.
